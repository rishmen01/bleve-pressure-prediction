## Workflow overview

1. **Data inspection:** checks column availability, target values, missingness, duplicate observations and categorical values.
2. **Cleaning:** removes labelled rows with missing targets and duplicate labelled observations (ignoring `ID`). Rows with at least 40% missing predictors are excluded from labelled training data; all competition test rows are retained.
3. **Category standardisation:** standardises observed `Status` spelling variants and normalises categorical identifiers.
4. **Feature engineering:** derives physical features such as tank ratio/volume, temperature and pressure relationships, obstacle volume and sensor distances.
5. **Scenario-aware splitting:** validates the 27-sensor ID sequence and groups readings from the same BLEVE scenario into a single train, validation or internal-test partition where the supplied ID/sensor pattern permits it.
6. **Leakage-aware preprocessing:** imputes, encodes, scales and clips predictor values within scikit-learn pipelines so fitted preprocessing is learned from the relevant training folds.
7. **Model comparison:** compares Linear Regression, Ridge Regression, Linear SVR, MLP Neural Network, Random Forest and XGBoost. Tuned models use grouped cross-validation and `RandomizedSearchCV`.
8. **Evaluation:** selects a candidate by validation MAPE, evaluates it once against the labelled internal-test holdout, then refits the selected procedure on all eligible labelled records.
9. **Prediction:** generates predictions for the unlabelled Kaggle `test.csv` and saves them to `outputs/prediction.csv`.

The default target-outlier setting retains extreme BLEVE pressure observations because they may represent meaningful physical cases. Predictor outlier clipping is fitted within the model pipelines. Review `REMOVE_TARGET_IQR_OUTLIERS` in the notebook before experimentation; do not remove extreme values without a justified analysis.

## Recorded run results

`RUN_RESULTS.md` and the CSV/JSON files in `outputs/` record a previous run on the supplied course datasets using scenario-aware splitting and a modest search configuration (2-fold grouped CV, 2 sampled configurations per tuned model). In that run, Random Forest was selected using validation MAPE:

- Validation MAPE: **0.28375**
- Validation R²: **0.83967**
- Internal-test MAPE: **0.25812**
- Internal-test R²: **0.83703**

These are local validation/internal-test results for the revised workflow, **not Kaggle leaderboard scores**. The original assignment's public Kaggle MAPE of `0.21306` belongs to the original submitted workflow and must not be attributed to this revised run. Re-running the notebook may produce different results if package versions or search settings change.

## Reproducibility notes

- Random state is set in the notebook for repeatable splits and searches.
- Scenario grouping is enabled only after checking the observed `ID`/`Sensor ID` relationship.
- `test.csv` has no labels, so MAPE and R² cannot be calculated for it. Use the labelled internal-test partition for local test metrics; Kaggle evaluates the generated submission separately.
- The modest search settings are intended to keep execution practical. Increase `CV_FOLDS` and `N_ITER_SEARCH` for a broader search when compute resources permit, then record the configuration and results.
